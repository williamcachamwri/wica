## Sprint Retrospective: Implementing Zero-Trust Analytics

Sprint 11 wrapped up with a heavy emphasis on access control and nailing down our live cloud deployments. Our main hurdle was refactoring dashboard metrics endpoints so they remain accessible to any logged-in user—regardless of role hierarchy like Admin, Editor, or Viewer—while keeping unauthenticated traffic blocked completely.

Instead of tying macro-level insights to strict Role-Based Access Control (RBAC), I overhauled the FastAPI backend to use a zero-trust `require_authenticated_user` dependency. By cleaning up Firebase ID token validation, we opened up quality trends and specialty distribution metrics to all valid users, ensuring unverified requests still hit a hard 401 Unauthorized wall. These changes went through our GitHub Actions pipeline and landed on Google Cloud Run, making our V1.0 backend architecture official.
